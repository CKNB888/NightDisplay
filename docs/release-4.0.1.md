# NightDisplay 4.0.1

修正版。功能、模式、界面和 4.0.0 一致：**默认走虚拟屏，本机真黑，远程画面不冻、不闪。**
这一版修掉了两处用户看得到的错误信息、诊断包里的一处脱敏错误，以及深度 QA 的等待逻辑。

## 下载

| 文件 | 适合谁 |
|---|---|
| `NightDisplay-4.0.1-Setup.exe` | 大多数人。装到当前用户目录，**不需要管理员**；驱动安装由程序里的向导负责，全程只弹一次 UAC |
| `NightDisplay-4.0.1-portable.zip` | 想放 U 盘、不装东西的人。解压即用，`resources\vdd` 里带着驱动 |
| `SHA256SUMS.txt` | 校验用 |

系统要求：**Windows 10 2004（build 19041）及以上，x64**。需要系统自带的 WebView2
（Win11 全都有；Win10 若没有，装一次微软的 Evergreen Runtime）。

## 这版修了什么

### 1. 诊断包不再把目录名、产品名当账号名改写

4.0.0 把"数据目录的最后一段"当账号名全局替换。Windows 上默认数据目录是
`%LOCALAPPDATA%\NightDisplay`，最后一段是**产品名**，结果诊断包里每一处 `NightDisplay`
都被抹成 `<user>`——`NightDisplay.exe` 变成 `<user>.exe`，真正的账号名反而没动。

现在只在数据目录本身就是一个用户主目录（上一段是 `Users` / `home`）时，才把最后一段当账号名
单独替换；路径里的账号名仍由 `\Users\`、`/home/` 标记的扫描处理。日志是 JSONL，路径里的反斜杠
被转义成 `\\`，4.0.0 的匹配没处理这种写法，`C:\\Users\\<账号>\\...` 这一整类行原样留在包里；
现在转义写法同样会被抹掉。

### 2. 黑幕模式下，夜间报告按真正执行的模式上报

`overlay` 生效时，报告曾经仍写「虚拟屏生效」：`effective` 只从配置里的 `cfg.mode` 推导，
而命令行 `--mode overlay` 和 `auto → 黑幕` 的自动降级都会覆盖这个值，于是 `virtual_screen`
是 `None`，成功判定永远为假，界面只显示「未知原因」——黑幕其实已经正常显示并排除了采集。

夜间修复 `ensure_night` 走的是同一条路。现在引擎负责把报告标注成这次**真正执行**的模式。
顺带修掉 overlay 兜底路径上的两处误报：`实体屏仍未接桌面` 在 overlay 下不成立也不该成立
（overlay 靠窗口遮黑、完全不碰拓扑）；`步骤没有失败` 不再把 gamma/背光算进去，
这两层是产品自己定义的可选增强，改成关键步骤继续卡着、增强层单独如实报告。

### 3. 深度测试补齐"重启后仍在时段内自动入夜"的等待

上一轮唯一失败的检查是这一项，读到 `state=day`。不是没入夜：`--action reconcile` 在
"计划已启用但常驻进程不在"时只负责把常驻进程拉起来就返回，真正按时间入夜由常驻进程
异步完成，测试拿到返回值立刻读配置，必然读到还没改的状态。现在等状态落定（最多 45 秒），
并把等待时长写进报告，以后能一眼分清"真的没入夜"还是"等得不够久"。

### 4. CI 从 `Cargo.toml` 读版本号

打包、深测、发布三个作业不再写死版本号，统一从 `[workspace.package] version` 读进
`APP_VERSION`，下次升版只改一行。标签与代码版本的一致性检查保留：`v4.0.1` 必须等于
`APP_VERSION`，否则打包作业直接失败。

## 从 4.0.0 升级

直接装新的就行，数据目录、配置和计划都不变（`%LOCALAPPDATA%\NightDisplay`），
不用重跑向导。

## 已知限制（请先读完再判断适不适合你）

* **不是所有显卡组合都能做到零闪**。下面这些情况仍然可能有一帧黑：
  驱动在 `SDC_APPLY` 内部重初始化输出（部分老 Intel 核显 + HDMI 外接）、
  实体屏和虚拟屏刷新率无法同时满足、多显卡跨适配器路径集被驱动拒绝、
  系统里已有第三方虚拟屏且命中匹配规则。程序保证的是"一次提交、不产生零 target、
  校验不过就什么都不改"，不保证每一台机器的驱动都配合。
* **DDC/CI 背光**在一体机和部分笔记本内屏上不可用。这类机器夜间是纯黑但背光仍亮，
  自检会点名是哪块屏。
* 采集排除的黑幕只在 Win10 2004+ 可用；系统接受了请求不等于每种远程采集方式都兼容。
* 断电、强制关机时看门狗也活不了，下次启动才恢复。
* **CI 没有在真实一体机上验证过**，也没法在 CI 里验证远程会话。没跑过的机型和远程软件，
  不标注为"已保证兼容"。
