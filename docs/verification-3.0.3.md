# 3.0.3 本地审计与验证

本轮基于 main 的 `4d8b88c` 和 3.0.2 修复候选继续审计，目标是把托盘、测试会话、IPC 和配置恢复路径补完整，并建立可重复执行的代码检查基线。

## 修改范围

- 托盘自启只唤醒已有常驻进程，不再重复弹出主窗口；托盘未在 2 秒内就绪时回退到主窗口。
- 测试中断、提前退出或恢复失败不再记为成功；启用计划要求实际解析出的模式与测试模式一致。
- Windows 10 2004 以下不提供防窥黑幕模式，避免调用不可用的 `WDA_EXCLUDEFROMCAPTURE` 能力。
- 配置校验覆盖运行时字段类型、额外时间段、正则表达式和组合键规范化；损坏的电源记录、显示备份不会阻断恢复。
- IPC 严格校验端口，关闭操作可重复执行；退出时中止未完成测试并再次尝试恢复显示。
- 计划状态识别额外时间段任务；日志目录不可写时不再影响显示或恢复操作。
- 增加 Ruff 配置和本地 lint 基线，修复未使用导入、异常链、文件句柄、导入顺序等问题。

## 未覆盖的边界

本轮没有在真实 UU/ToDesk 会话中验证远程画面，也没有重新安装内置 VDD 驱动。防窥黑幕的 `WDA_EXCLUDEFROMCAPTURE` 只验证了 API 可用性和模式选择，不能证明每一种远程采集方式都兼容。

macOS 和 Linux 没有在本轮 Windows 主机上重新运行；对应路径仍依赖 CI runner 和真机检查。实体屏背光、拔插显示器、驱动更新后的行为需要实际设备确认。

VDD 驱动二进制没有写入源码仓库；源码构建仍通过 `tools/download_vdd.py` 下载并校验固定版本的 ZIP。

## 代码检查基线

`pyproject.toml` 增加了 Ruff 配置，启用 `E4`、`E7`、`E9`、`F`、`B`、`SIM`、`I`、`UP`，并保留现有代码中的长行、单行紧凑语句和 `%` 格式化。当前提交的 lint 检查在本地执行；工作流文件未在本分支修改。
