# 验证记录与实机调试清单

## 已进行的静态检查

- 核对 PowerShell 的主要分隔符和 here-string 配对：无未闭合项（基于脚本扫描，非 PowerShell 引擎解析）。
- 核对每天 20:00、10:30 两个触发器与登录校准入口均存在。
- 验证时间判断边界：00:00、10:29、10:30、19:59、20:00、23:59 共 6 个断点逻辑一致。
- 检查实验模式的执行顺序：先创建测试恢复任务，再扩展虚拟显示器，最后进入第二屏独占。
- 检查安装默认暂停任务；只有测试完成并由用户确认后，才能启用每日任务。
- 检查恢复入口和卸载入口具备可见的任务撤销机制。

## 未验证、不能声称通过的项目

- **未在 Windows 10/11 的 PowerShell 5.1 中执行**或使用其解析器验证语法。
- 未安装/测试 Virtual Display Driver，也未验证 Windows 的 `/external` 和 `/internal` 在任何具体一体机上的实际显示顺序。
- 未连接网易 UU 远程验证其虚拟显示器选择、断线重连、鼠标与键盘响应。
- 未验证一体机物理屏背光是否彻底熄灭；无法保证本地按键不会重新影响显示。
- 未验证 BOSS 直聘后台在线、Windows 睡眠策略和其他软件兼容性。

## 建议实机测试顺序

1. 用菜单 2 记录系统版本、设备品牌型号、显卡、VDD 识别结果。
2. 菜单 1 安装，菜单 7 确认三个任务默认 Disabled。
3. 菜单 3：基础关屏，测试鼠标唤醒，等待 120 秒自动恢复，检查日志。
4. 安装官方或可信渠道的签名 VDD，确认实体显示器是 1，VDD 虚拟显示器是 2。
5. 手动选择 Windows 扩展屏，先验证 UU 能从远程控制虚拟桌面。
6. 菜单 4：实机观察 `/extend` → `/external` 是否让物理一体机黑屏，UU 画面是否存在。
7. 测试过程中断开 UU，重新连接，并在 120 秒后检验 `/internal` 是否恢复物理屏。
8. 只有上述通过才选菜单 6 启用自动任务。
9. 临时通过 Windows 任务计划程序执行各任务，分别核对夜间、白天状态与记录。
10. 第二天检验 20:00 和 10:30 的自然触发；验证异常网络断开及重启/登录后是否能恢复。

## 发现问题时向开发者提供

- Windows 版本（Win+R → `winver`）和一体机品牌、型号。
- Windows 设备管理器中的“显示适配器”名称。
- 显示设置中的屏幕 1/2 编号截图。
- 使用的 UU 客户端版本和当时是否开启 UU 自带隐私屏/超级屏。
- `%LOCALAPPDATA%\NightDisplay\nightdisplay.log` 的相关时间段（先删除其中你不愿分享的个人信息）。
- 具体失败环节：无法安装任务、黑屏不持久、UU 看不到、无法恢复、重启后状态错误等。

## 版本边界

这个 ZIP 是可进一步调试的**开发原型**，不是已经在用户具体机器上验收的 UU 隐私屏实现。严禁在无法现场恢复显示的关键工作设备上直接启用 `VirtualOnly` 每日自动化。
