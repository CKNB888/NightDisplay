# NightDisplay 4

按计划把这台电脑的屏幕变黑 —— **本机看是纯黑，远程软件照常能看到桌面、照常能操作**。

和旧版的区别：4.0 是 Rust 重写，默认模式换成了「防窥黑幕」，
从根上解决了旧版最难受的三个问题：

| 旧版现象 | 原因 | 4.0 的做法 |
|---|---|---|
| 点黑屏那一瞬间远程就卡住，得重新连一次 | 默认模式会调用 `SetDisplayConfig` 把实体屏从桌面布局里摘掉，远程软件的采集面跟着消失 | 默认模式**完全不碰显示拓扑**：黑幕是一层覆盖在每块屏上的窗口，远程采集的是窗口下面的桌面 |
| 远程进去先亮一秒才变黑 | 改拓扑会让显示器重新同步，中间有一瞬是正常画面 | 黑幕窗口在常驻进程启动时就建好藏起来，夜间只是 `ShowWindow`，首帧延迟会写进日志 |
| 黑屏期间一碰鼠标、一开远程就亮了 | 关屏/虚拟屏都挡不住输入唤醒 | 夜间吞掉本机真实键鼠事件，放行远程注入的事件；并抑制锁屏 |

作者：传康Kk。赞助及联系：1837620622。

[下载正式版本](https://github.com/CKNB888/NightDisplay/releases/latest) · [反馈问题](https://github.com/CKNB888/NightDisplay/issues)

> **平台**：4.x 只支持 **Windows 10 2004（build 19041）及以上**。
> macOS 和 Linux 支持在 4.0 里取消了 —— 旧版在这两个平台上从来没有真正做到"本地黑屏、远程正常"，
> 与其留着半成品，不如把 Windows 这一条路做扎实。3.x 的代码保留在 [`legacy-python/`](legacy-python/)。

## 一、它是怎么黑屏的

夜间由三层叠加，从下到上：

### 第 1 层：防窥黑幕（必需，决定模式成败）

每块显示器盖一层纯黑窗口：

* 无边无框、置顶、不抢焦点、点击穿透；
* 用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 把自己**排除在屏幕采集之外**，
  并且**校验**系统真的接受了这个设置 —— 校验不过就把黑幕收回、如实报错，绝不谎报"已黑屏"；
* 所以本地看到的是纯黑，远程采集到的是黑幕下面的真实桌面。

这一层成功，夜间就算成功。

### 第 2 层：gamma 拉到 0（尽力而为）

对每个显示输出把 gamma ramp 清零，屏幕会变成真正的黑，背光也暗下去一些。
gamma 作用在输出链路上，**不进采集画面**，所以远程不受影响。
驱动拒绝时只记一条日志，不影响夜间。

### 第 3 层：DDC/CI 背光调到 0（尽力而为）

通过 `dxva2` 找到每块物理面板，把 VCP `0x10`（亮度）设成 0，并每 5 秒重新压一次
（显示器自己的省电策略、菜单按钮都会把亮度拉回来）。

一体机、部分笔记本内屏不支持 DDC/CI，这类面板会跳过并在自检里写明，**属于正常限制**，
不是故障。

### 输入与锁屏

* **严格本地防触控**（默认开）：装一个低级键鼠钩子，夜间吞掉**真实硬件**的键盘鼠标事件；
  **带注入标记的事件全部放行**，所以远程软件的操作一点不受影响，远程也能正常解锁、点开始菜单。
* **夜间抑制锁屏**（默认开）：不抑制的话，登录界面会盖住黑幕，本机就能看到桌面。
  程序每 60 秒发一次无害输入重置空闲计时。

> **安全权衡（请自己评估）**：抑制锁屏意味着夜间这台电脑**不会因为闲置自动锁屏**。
> 如果你所在的场景对物理安全敏感（例如公共场所），请在设置里关掉「夜间抑制锁屏」，
> 或者不要在有人的时段使用计划。程序不会绕过任何组策略强制锁屏；组策略强制锁屏时，
> 锁屏界面会盖住黑幕，这属于预期行为。

### 关于另外两种模式

`virtual_only`（仅虚拟屏）和 `screen_off`（基础关屏）**只能由用户手动选择**，
**永远不会出现在自动降级链里**，界面上都标着「会中断远程连接」：

| 模式 | 本机效果 | 远程影响 |
|---|---|---|
| `auto` / `guard`（默认） | 纯黑 | 无影响，画面照常 |
| `virtual_only` | 只剩虚拟屏 | **会断一次**，远程软件要重连 |
| `screen_off` | 显示器休眠 | 动鼠标即亮，远程重连可能唤不醒 |

`virtual_only` 还要求装了虚拟显示驱动（见下面的向导第 2 步）。

## 二、第一次运行：一个向导，一次授权

```
NightDisplay --action setup
```

首次运行只有这一个向导，**全程只弹一次管理员确认（UAC）**，之后夜间切换再也不弹：

| 步骤 | 做什么 | 结果怎么显示 |
|---|---|---|
| 1 授权并准备后台服务 | 拉起一个常驻的**提升助手**（提权服务），后续所有需要管理员的事都交给它 | 成功 / 你在 UAC 点了"否"（带日志链接） |
| 2 虚拟显示驱动（可选） | `pnputil` 静默安装包内内置的 VDD | 默认**跳过**；勾选「兼容老远程软件」才装 |
| 3 开机自启与看门狗 | HKCU Run 键 + 计划任务 + 登录时拉起的看门狗 | 每一项单独报告，被安全软件拦下时给出确切的手动命令 |
| 4 本地防触控与锁屏 | 写配置并立刻验证这条链路能用 | 成功 / 失败时说明哪一项、去哪里手动开 |
| 5 15 秒自检 | **真的黑屏 15 秒**再自动恢复，附远程连接检查提示 | 报告每块屏、首帧延迟、gamma/背光的真实结果 |
| 6 确认远程能连 | 勾选「已确认远程能连」，向导结束 | 勾了才算完成 |

规则：

* **每一步都报告真实结果**：`成功` / `已跳过` / `需要手动处理（附确切命令或链接）`，
  不会只给你一句"失败了"。
* 完成状态写在 `onboarding.json`，**装完之后永远不会再自动弹出**。
* 任何一步失败，可以在设置里点 **「重新授权 / 修复」**（命令：`NightDisplay --action repair`），
  它**只重跑失败的那几步**，不会把你已经配好的东西再折腾一遍。
* 某一步失败时，向导会直接给出日志目录，点开就有完整错误链。

### 为什么是"一个提升助手"

* GUI / CLI **自己永远不以管理员身份运行**；
* 需要管理员的事（装驱动、登记计划任务、装看门狗）全部转给一个提升助手进程；
* 助手的 IPC 面是一个**白名单**：`ping`、`install-vdd`、`uninstall-vdd`、`install-tasks`、
  `remove-tasks`、`install-watchdog`、`quit`，除此之外什么都干不了；
* 通道是命名管道 + 32 字节随机令牌（存在只有本用户能读的数据目录里），
  并且 `PIPE_REJECT_REMOTE_CLIENTS`，远程机器连不上；
* 登记计划任务时只接受 `HH:MM` 时间点字符串，**不接受任何路径或命令行**，
  所以即使令牌泄露，也没法借助手执行任意程序。

## 三、装好之后

```text
NightDisplay --action test --seconds 15          黑 15 秒再自己亮回来（不改已有计划）
NightDisplay --action activate --start 20:00 --end 10:30   启用每日计划
NightDisplay --action status                     看当前状态
NightDisplay --action pause                      暂停每日计划（不改当前屏幕）
NightDisplay --action emergency                  立刻亮屏并暂停（可远程执行）
NightDisplay --action serve                      常驻进程（托盘/计划任务都调它）
```

启用计划必须先有一次**成功的测试**：测试结束、屏幕自己亮回来，才算数；
超过一天、或者换了显示器/显卡驱动（能力指纹变了），都要重测。

### 怎么亮回来（四个办法，都不需要远程会"点"

1. **本机按住 C + K 约 0.3 秒**（可改键、可改时长）。组合键解锁后，本段剩余时间不再黑屏。
2. **远程执行** `NightDisplay.exe --action emergency`，随时有效，不受锁定限制。
3. **计划到点自动恢复**。
4. **看门狗**：主进程被结束后几秒内自动把 gamma、背光、拓扑全部还原。

### 看门狗

登录时由计划任务拉起，常驻一个轻量进程，盯着主进程的 PID：

* 主进程消失 → 立刻从 `screen-state.json` 还原 gamma 和背光（必要时还原拓扑），
  把配置写回白天，然后按需重启常驻进程；
* 主进程正常退出前会先写 `watchdog.json` 标记，看门狗看到标记就自己退出，不会误杀。

这一条很关键：**只靠主进程里的线程是不够的**，用户"结束任务"时线程一起死，
屏幕就永远停在 gamma 0，看起来像显示器坏了。

## 四、命令行

与旧版保持一致的 `--action`，外加 4.0 新增的向导与常驻进程：

| 动作 | 说明 |
|---|---|
| `setup` | 首次运行向导（只弹一次 UAC） |
| `repair` | 重新授权 / 修复：只重跑上次失败的步骤 |
| `onboarding` | 打印向导每一步的真实结果 |
| `serve` | 常驻进程：定时对齐 + 本地 IPC + 组合键 |
| `status` / `selfcheck` / `env` / `displays` | 诊断 |
| `night` / `day` / `reconcile` | 手动进入夜间 / 恢复白天 / 按计划对齐一次 |
| `test` / `activate` / `pause` | 测试 / 启用 / 暂停 |
| `emergency` / `uninstall` | 应急恢复 / 卸载（恢复 + 删任务 + 关自启） |
| `plan-virtual` | **只演练**「仅虚拟屏」，不改任何显示设置 |
| `backup` / `restore` | 备份 / 还原显示配置 |
| `install-vdd` / `uninstall-vdd` | 安装 / 卸载内置虚拟显示驱动 |
| `awake` | 保持唤醒 N 秒 |
| `update` | 检查新版本（链接永远指向本仓库） |
| `watchdog` / `helper` / `quit` | 内部使用 |

选项：`--mode`、`--start`、`--end`、`--delay`、`--seconds`、`--test-id`、
`--test-recovery`、`--parent`、`--home`、`--vdd`、`--only`、`--debug`、`--tray`。

退出码：`0` 成功 / `1` 出错（屏幕状态会尽量保持安全） / `2` 黑屏锁定中拒绝本地恢复。

`--debug` 会把完整错误链打到终端；正常情况下只有一句中文，完整堆栈写到 `logs/traceback.log`。

## 五、数据目录与文件

默认 `%LOCALAPPDATA%\NightDisplay`（可用 `--home` 或环境变量 `NIGHTDISPLAY_HOME` 覆盖）：

| 文件 | 内容 |
|---|---|
| `config.json` | 计划、模式、组合键、开关（**同时镜像旧版的 `start`/`end`/`extra_ranges`**，可以随时退回 3.x） |
| `onboarding.json` | 向导是否完成、每步的真实结果、需要修复的步骤 |
| `screen-state.json` | 夜间开始时的 gamma、背光、拓扑快照（看门狗靠它恢复） |
| `ipc.json` | 常驻进程的令牌与管道名 |
| `helper-token.txt` | 提升助手的令牌 |
| `daemon.lock` | 常驻进程单实例锁 |
| `backups/` | 显示配置备份（最近十份轮转） |
| `logs/YYYY-MM-DD.log` | 按天分文件，保留 30 天 |
| `logs/traceback.log` | 完整错误链 |

## 六、出问题时

| 现象 | 先做什么 |
|---|---|
| 远程黑屏期间看不到画面 | 跑 `--action selfcheck`，看"采集排除"是否可用。不可用说明系统低于 Win10 2004，黑幕无法保证远程可见 |
| 屏幕黑了但背光还亮着 | 正常限制：这块面板不支持 DDC/CI。自检里会点名是哪块屏 |
| 提示"提权助手没启动" | UAC 里点了"否"或被杀软拦了。点「重新授权 / 修复」，或右键 exe 选"以管理员身份运行" |
| 计划任务登记失败 | 向导会给出确切的手动命令；常见原因是组策略限制或安全软件拦截 |
| 屏幕一直是黑的，什么都做不了 | 本机按住 C + K；或远程执行 `--action emergency`；或看门狗在几秒内自动恢复 |
| 开机后没有自动进入夜间 | `--action status` 看"开机自启：配置=开 实际=?"。实际=关 说明被「启动」项或安全软件禁用了 |

日志在 `%LOCALAPPDATA%\NightDisplay\logs`。报问题时给版本号、`selfcheck` 输出和对应那天的日志就够了，
不需要提供远程账号或密码。

## 七、能保证什么，不能保证什么

**能保证**：黑幕显示失败时会立刻撤回并报错，绝不假装成功；
gamma 和背光的原始值都会存盘，主进程被杀也有看门狗兜底；
默认模式不改显示拓扑、不改分辨率、不改 DPI。

**不能保证**：

* `WDA_EXCLUDEFROMCAPTURE` 只是 Windows 接受了请求，**不能证明每一种远程采集方式都兼容**。
  UU、ToDesk、RDP 的实际画面请自己各试一次（向导第 5 步就是为这个准备的）；
* 一体机和部分笔记本内屏不支持 DDC/CI 背光，这类机器夜间是纯黑但背光仍亮；
* 断电、关机、低电量保护、组策略强制锁屏，程序管不了；
* 本仓库的 CI 只在托管机上编译和跑单元测试，**没有在真实一体机上验证过**，
  也没法在 CI 里验证远程会话。没跑过的机型和远程软件，不标注为"已保证兼容"。

## 八、构建与测试

```bash
cargo test -p nd-core                 # 纯逻辑：时间计划、组合键、配置迁移、模式降级、向导状态
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release --target x86_64-pc-windows-msvc -p nightdisplay
```

工作区结构：

```
crates/nd-core   纯逻辑（无平台调用，Linux 上也能测）
crates/nd-win    Windows 实现：黑幕、gamma、背光、输入钩子、计划任务、助手、看门狗
crates/nd-cli    命令行与常驻进程（NightDisplay.exe）
resources/       安装包资源（install_vdd.ps1、VDD 配置）
legacy-python/   3.x 的 Python 实现，留作行为对照
```

CI（`.github/workflows/rust.yml`）：

* `windows-latest`：`fmt --check` → `clippy -D warnings` → `test --workspace` → release 构建 → 命令行冒烟；
* `ubuntu-latest`：只跑 `nd-core` 的单元测试（时间计划和配置迁移都是纯逻辑）。

旧版 Python 的构建和发布只保留在 `main` 和 tag 上（`.github/workflows/build.yml`），
重写分支不占用 runner。

## 九、更新记录

### 4.0.0（进行中）

* Rust 重写，只保留 Windows。
* **默认模式改为防窥黑幕**：不再改动显示拓扑、分辨率、DPI，远程画面不会因为黑屏而断流或闪一下。
* 三层叠加：采集排除的黑幕（必需）+ gamma 归零 + DDC/CI 背光归零（后两层尽力而为，逐块报告）。
* 黑幕窗口在常驻进程启动时预热，夜间只剩显示动作，首帧延迟写入日志。
* 严格本地防触控：吞真实键鼠、放行注入事件，远程操作完全正常。
* 夜间抑制锁屏，避免登录界面盖住黑幕（安全权衡见上文）。
* 四条安全线：组合键解锁、到点自动恢复、`--action emergency`、独立看门狗进程。
* **首次运行向导**：一次 UAC、六个步骤、每步真实结果、完成后永不再弹、
  设置里「重新授权 / 修复」只重跑失败步骤。
* 所有特权动作收敛到一个提升助手，GUI 始终不以管理员身份运行。
* `virtual_only` / `screen_off` 降级为**只能手动选择**，界面与文档都标注会中断远程。

3.x 的更新记录见 [`legacy-python/README.md`](legacy-python/README.md) 与历史提交。
